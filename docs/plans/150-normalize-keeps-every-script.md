# #150 -- normalize keeps the letters of every script, so a non-Latin title or artist compares as itself and never as ""

Epic #237 child, S. Behaviour change (what `normalize` returns for non-Latin, Latin-extended and punctuation-only text, and everything that compares its results): the three-reviewer gate applies. Lands AFTER #191 (it edits the adjacent apostrophe line of `normalize`; conflicts otherwise), on the same lane.

## Plan (execute as written)

Written 2026-10-08 against `main` at `9de5f29`. Cites are to that tree; re-find by function name.

### What is wrong

`normalize` (`plugins/music/src/matching.ts:50-66`) ends with `.replace(/[^a-z0-9]+/g, " ")`, the only character class in the pipeline, so every non-Latin title or name becomes `""`. YOASOBI's "夜に駆ける" normalises to `""`; every other all-kanji candidate by YOASOBI then scores title 100 (`titleScore`, `:165`, `candidate === song`) plus artist 40, is `exactTitle && exactArtist` (`pickBestTrack`, `:347-348`), and the page-order first is added as `high` with no flag, wrong whenever the right track is not first. For a non-Latin performer (Кино) with a non-Latin title, `exactArtist` is true for any non-Latin-named artist. `artistScore` (`:226-234`) gives any candidate with a non-Latin (so empty) artist name a spurious 22 against any wanted artist, because `"queen".includes("")` is true. The set-level helpers treat all non-Latin names as equal: `preferExactArtist` (`setlistfm.ts:303-307`), `creditedArtist` and `searchArtistsFor` (`artists.ts:39-57`, `:78-90`, which de-duplicates by `normalize`, so two different non-Latin names collapse to one), and the nearest-match warning (`commands.ts:137`). Nothing in the tests or the replay corpus carries a non-Latin string.

### Decisions

- **Letters and digits of any script survive.** The class becomes `/[^\p{L}\p{N}]+/gu`. NFD plus the combining-mark strip and `toLowerCase()` still fold accented Latin to its base letter and case, so every Latin result is unchanged except that a letter with no decomposition (`ø`, `ß`, `æ`, `ł`) is now kept instead of becoming a space: "Bjørk" is `bjørk`, not `bj rk`. That is a correction, not a regression (two spellings that differed before still differ), and the plan doc and the bullet say it.
- **A result that would be empty is the input itself, trimmed and lower-cased,** so two punctuation-only titles ("???", "...") are not equal; the comment says why.
- **An empty candidate artist scores nothing.** `artistScore` skips `""` before the `includes` checks (a punctuation-only artist name is now its own text, so this is the belt for the empty case that remains: a candidate with no artist names at all, or one that is whitespace).
- **Nothing else changes.** `titleScore`'s length floors count characters, which is right for CJK too (one character is one syllable or word); `withinOneEdit` and `MIN_TYPO_TITLE_LENGTH` likewise. The set-level helpers are fixed by `normalize` itself.
- **No version bump.** The CHANGELOG bullet travels in the PR body (see the steps).

## Deviations as implemented

- **Combining marks are kept (the class became a word pattern).** The plan's `/[^\p{L}\p{N}]+/gu` treats a combining mark as punctuation, and NFD splits more than accents: a kana with a voiced mark (`ガ` = `カ` + U+3099), Indic vowel signs and viramas, Thai tone marks and vowels. Reproduced before and during the gate (both reviewers found it independently): `ガ` equalled `カ`, `バンド` equalled `バント` (so a wrong track reached `high`), `ไม่` equalled `ไม้`, `दिल` equalled `दाल`, and a mark opened a gap inside its word, which made `ロード` a "prefix" of `ロードショー` (title 72, `medium`). `normalize` now takes words as `/[\p{L}\p{N}][\p{L}\p{N}\p{M}]*/gu` (a mark with no letter before it, such as an emoji variation selector, goes with the punctuation) and recomposes the result to NFC, which also makes a Hangul syllable one character again (NFD had made `사랑` five, so `titleScore`'s length floors counted jamo). A bare `\p{M}` in the class would have been wrong: it leaves a variation selector behind.
- **Claims in the plan corrected here, not edited above:** (a) "every Latin result is unchanged except [letters with no decomposition]": non-ASCII digits and letter-like characters (`²`, `½`, `Ⅳ`, `③`, `º`, `ʿ`, the `ﬁ` ligature, full-width `ＡＢＣ`) are now kept too, where they were dropped; (b) "`titleScore`'s length floors count characters, which is right for CJK" was false for Hangul and voiced kana until the NFC step; (c) Coverage rows 1 and 5, "restore `[^a-z0-9]`": with the empty-result fallback kept, a pure non-Latin string still comes back as itself, so those tests alone stay green under a class-only revert. The class is pinned by the cased, punctuated and mixed-script assertions added for it, and a full revert (class and fallback) turns 25 tests red in `plugins/music` (the mutation run in the PR body); (d) "a candidate with no artist names at all" cannot reach the `artistScore` guard (an empty array never enters the loop), only a blank string can; (e) "Nothing in the tests carries a non-Latin string" was stale against its own base: #155's test used `米津玄師` and asserted it normalises to `""`, which is now false by design, so that test was edited (blank names for the guard, plus a positive test for a non-Latin artist in a `/party add` query); (f) the line citations were found by function name, as the plan says (at the merged head `preferExactArtist` is `setlistfm.ts:313-317` (#191 moved the file five lines) and the nearest-match note is `commands.ts:138`).
- **Disclosed trade-offs and declined follow-ups (not in the issue):** a title or name written in two scripts (`Lemon (レモン)`, `Hikaru Utada (宇多田ヒカル)`) must now match in both, where it used to reduce to its Latin half; compatibility forms are not folded (`ＢＴＳ` is not `BTS`, `Ⅳ` is not `IV`; NFKD would also turn `Song™` into `songtm`, so it is its own decision); the accent fold applies to every script, so `й` folds to `и` and `ё` to `е` as `é` folds to `e`; `º` (a letter) no longer equals `°` (a symbol). A non-Latin primary artist now earns the tie-break count, which was always 0 while its name read as `""`; a test pins it.
- **CHANGELOG bullet:** the plan's text, plus one clause saying a title written in two scripts must match in both (see the PR body).
- **More disclosed trade-offs (gate round 2), none fixed here.** A zero-width non-joiner or joiner (U+200C/U+200D, category Cf) is a separator, as every non-letter was, so a Persian word written with one reads as two words (`می‌خواهم` is `می خواهم`, not `میخواهم`) and `क्‍ष` splits; stripping them is a choice for Persian and Indic text, not an oversight. A variation selector, keycap or enclosing mark that follows a letter or digit stays attached (`1️⃣` is not `1`), which is the rule "a mark belongs to its letter". Hebrew points and Arabic harakat are marks, so vocalised text no longer equals the same text without them (`שָׁלוֹם` is not `שלום`), while Cyrillic and Greek accents fold (`й`, `ё`, `έ`): the asymmetry is the existing accent-strip range (U+0300-U+036F) applied to every script. The empty-result fallback is not NFC-folded, so two byte sequences for one letterless symbol differ; only letterless text reaches it. The predicted merge conflict with #191 did not occur: its apostrophe line sits five lines above the word pattern.
- **Survivors declined, with the reason.** NFC replaced by NFKC, `\p{N}` narrowed to `\p{Nd}`, and the fallback in NFD form stay green. The first two change only how `²`, `½`, `Ⅳ`, full-width Latin and the `ﬁ` ligature compare, which nobody has chosen (and NFKD would turn `Song™` into `songtm`); the third differs only for a few canonically decomposable symbols that no title uses. `.filter((artist) => artist !== "")` in `pickTrackFromQuery` is now an equivalent mutant behind the `artistScore` guard, and is left as defence in depth.
