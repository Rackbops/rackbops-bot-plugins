# rackbops-bot-plugins

Plugins for [Rackbops/rackbops-discord-bot](https://github.com/Rackbops/rackbops-discord-bot),
published as npm bundles plus a Plugin Index (`plugins.json`) any bot instance fetches. Design:
that repo's `docs/adr/0004-plugins-fetched-from-a-published-manifest.md`.

Public, deliberately: the bot's image build fetches `plugins.json` and the npm tarballs with no
credentials (the bot repo's `README.md`: "the daemon fetches the build context itself, with no
credentials"), and the packages are public on npm regardless.

## Local environment

- **Bun** -- `bun@1.3.14` (pinned via `packageManager`, matching `rackbops-discord-bot`'s pin).
- **Environment variables** -- none required to develop this repo itself. Each plugin declares
  its own via its `package.json`'s `botPlugin.env` block (consumed by the bot at runtime, not by
  anything here).

## Layout

| Path | Contents |
|---|---|
| `plugins/` | One directory per plugin: `package.json` (with a `botPlugin` block), `src/`, `CHANGELOG.md`, tests. Empty until a plugin is added. |
| `packages/api/` | `contract.d.ts` -- the host<->plugin contract, vendored verbatim from `rackbops-discord-bot`'s `src/plugins/contract.ts`. Type-only: import with `import type`, never a runtime import -- see `CONTEXT.md`. |
| `scripts/` | `generate-index.ts` (plugins -> `plugins.json`), `check-contract.ts` (drift check against upstream), `build-plugins.ts`. |
| `plugins.json` | Generated by `scripts/generate-index.ts`. Committed. Never hand-edit -- `publish.yml` is the only thing besides a manual regenerate that changes it. |

## Testing

- `bun run check` -- typecheck.
- `bun test` -- unit tests.
- `bun run generate-index -- --check` -- verifies `plugins.json` matches what the plugins on disk would generate.
- `bun run check-contract` -- verifies `packages/api/contract.d.ts` hasn't drifted from upstream. Needs network access (fetches `rackbops-discord-bot`'s live `main`) and fails if that repo is unreachable.

All four run in CI on every PR and push to `main`. **A green CI run is not proof a plugin behaves
correctly in the bot** -- see `rackbops-discord-bot`'s own testing docs for what only an in-app run proves.

## Publishing

A plugin tagged `<name>-v<semver>` triggers `.github/workflows/publish.yml`: verify the tag
matches the package version and the CHANGELOG has a section for it, build, `bun publish`,
regenerate and commit `plugins.json`, cut a GitHub release with the CHANGELOG section as the
body. Publishing is the only path that changes `plugins.json`'s versions -- hand-edits are
forbidden.

## Not in this repo

No Discord release announcements (`sync_webhooks.py`) -- plugin releases aren't WoW-community
announcements, unlike the addon repos this org otherwise maintains.
